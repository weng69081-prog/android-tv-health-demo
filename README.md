# TV 设备运行健康平台（Demo v0.2）

基于「Android TV OS 运行健康数据分析与可视化系统」需求做的可运行原型。
**数据源为数据分析岗交付包**（`mock_log_data.csv` / `stats_result.json` / `dashboard_data.json`），
**口径严格按交付包说明书 5 条铁律，未改动**。

## 四个页面

| 页面 | 角色 | 内容 |
|---|---|---|
| `index.html` 健康概览 | 开发岗 | 整体健康度、崩溃率、开机异常率、开机耗时、版本 KPI、8 周崩溃趋势、Top5 崩溃设备、最近告警、AI 智能分析（可下钻明细） |
| `verify.html` 口径与验证 | 数据分析岗 | 5 条铁律口径、KPI 与明细一致性对账、崩溃归因拆解、开机异常率构成、开机耗时分布、分析结论 |
| `perf.html` 接口与压测 | 开发岗 | 5 并发压测实测结果（P95 / 成功率 / 并发）、六个查询接口清单、启动方式 |
| `issues.html` 已知问题 | 团队 | 6 条已知问题与改进方案、下一步排期 |

## 5 条铁律口径（不得改动）

1. 总开机次数 = 全部记录条数（正常 + 开机慢 + 异常崩溃）
2. 异常崩溃次数 = `status = 异常崩溃` 的记录数
3. 崩溃率 = 异常崩溃次数 ÷ 总开机次数 × 100%
4. 开机异常率 = (异常崩溃次数 + 开机慢次数) ÷ 总开机次数 × 100%
5. 健康度得分 = 100 × (1 − 崩溃率小数形式)

## 查询服务

```bash
python server.py      # 零依赖，默认 127.0.0.1:8010
python bench.py       # 5 并发压测，复现 perf 页数字
```

接口：`/api/summary` `/api/kpi` `/api/trend` `/api/devices` `/api/detail` `/api/attr`

## 已知的数据一致性说明

交付包 `stats_result.json` 基于 3000 条主数据集，`mock_log_data.csv` 明细为 1000 条，
两者数值不可直接相加（交付包说明书已注明）。本系统页面统一使用**明细复算值**，
并在 `verify.html` 保留交付包原值做对账展示，保证每个数字都能下钻到原始记录。

## 文件

- `index.html` / `verify.html` / `perf.html` / `issues.html` — 四个页面
- `style.css` — 公共样式
- `merge.js` — 由交付包数据整合生成（含 1000 条明细，用于可追溯下钻）
- `mock_log_data.csv` — 交付包原始明细（服务端数据源）
- `server.py` / `bench.py` / `bench_result.json` — 查询服务与压测
- `gen_merge.py`（工作区）— 数据整合与归因计算脚本
- `echarts.min.js` — 图表库（本地引入，无外网依赖）
